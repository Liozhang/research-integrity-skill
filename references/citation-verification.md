## 两层保证：真实 ≠ 有效

| 关卡 | 定义 | 判据 | 防什么 |
|---|---|---|---|
| **第一关 真实** | 这篇文献存在，且就是我读的那篇 | URL 可达 + 页面标题与表中标题一致 + 作者/年份/期刊/DOI/PMID 可核验 | 捏造文献、张冠李戴、把 A 研究结论安到 B 研究上 |
| **第二关 有效** | 该文献正文确实支持被引的那一句，且级别与时效够 | 正文有支撑原句 + 来源级别（一级>二级>三级）+ 数据年份/版本适用 | 错引（文献真实但不支持该句）、过度引申、厂商宣传当独立证据、二手转述当原始、RUO 说成临床可用 |

**代码能判第一关的全部和编号/格式纪律；第二关的"正文是否支持该句"必须人审或模型回原文定位，代码只负责强制你把证据显式写出来（来源级别、验证状态、访问日期）。**

## 单条引用的六步生命周期

```
① 检索命中    记录 URL + 标题 + 来源类型 + 检索词 → 进检索日志
② 读到正文    web-reader / WebFetch；403/CAPTCHA → 升级浏览器通道
              仍失败 → 验证状态记「待验证」，禁止作为关键结论主证据
③ 字段核对    作者/年份/期刊/卷期页/DOI/PMID 逐项与检索结果比对
              任一项对不上 → 删该项，不做合理化补全
④ 有效性判定  正文中找到支撑被引那句的原句；找不到 → 改引或删结论
              来源是综述/新闻/厂商页 → 标二级，不得单独支撑关键量化结论
⑤ 编号登记    五元组锁定：编号 ↔ URL ↔ 访问日期 ↔ 来源级别 ↔ 验证状态
⑥ 交付前回点  citation_audit.py 全量审计 + 人工核对编号与字段
```

## 哪些规则由代码强制

`scripts/citation_audit.py report.md --pmid-api`（报告级审计，退出码 0=PASS / 1=仅 WARN / 2=FAIL / 3=输入错误）：

| 规则 | 严重度 | 代码判据 |
|---|---|---|
| 「参考文献」小节与表格存在 | FAIL | 标题 `## 参考文献` + 带表头的 markdown 管道表 |
| 编号从 1 连续、无重复 | FAIL | `编号序列 == [1..n]` |
| 每条有 URL 且为 http(s) | FAIL | 正则 + 协议头 |
| 访问日期存在、是有效日历日期、不晚于今天 | FAIL | `date.fromisoformat`（拒绝 2026-13-99）+ 与当天比较 |
| 来源级别 ∈ {一级,二级,三级} | FAIL | 枚举 |
| 验证状态 ∈ {已读全文,待验证} | FAIL | 枚举 |
| **PMID 在 PubMed 真实存在** | FAIL | NCBI E-utilities `esummary` 返回无 error（`--pmid-api`） |
| 标题与权威元数据/页面标题一致 | FAIL | 归一化后双向包含 / 期望词覆盖 ≥0.8 / Jaccard ≥0.6 |
| 年份、期刊与权威元数据一致 | WARN | pubdate 包含年份；期刊名互相包含 |
| URL 可达 | FAIL | HTTP GET（403/429/503、反爬过渡页、DOI 重定向页归 BLOCKED） |
| 正文无悬空引用 | FAIL | 正文 `[n]`/`[n,m]`/`[n-m]` 编号 ⊆ 表中编号 |
| 无孤引 | WARN | 表中编号 ⊆ 正文引用编号 |
| 同一 URL 不重复计数 | WARN | URL 去重统计 |
| BLOCKED 条目 | WARN | 命中反爬特征 / 过渡页标题 |
| 待验证条目 | WARN | 验证状态枚举 |

**权威元数据 API 优先于页面抓取**（这是"确定性由代码保证"的关键分工）：

| 场景 | 通道 | 判据 |
|---|---|---|
| URL 是 PubMed PMID | `eutils.ncbi.nlm.nih.gov/.../esummary.fcgi?db=pubmed&id=<pmid>` | PMID 是否存在 + 标题/期刊/卷期页/作者/DOI |
| URL 是 PMC 文章 | `ncbi.nlm.nih.gov/pmc/utils/idconv/v1.0/?ids=PMCxxx` 先转 PMID，再 esummary | 同上 |
| 有 DOI | `api.crossref.org/works/<DOI>` | DOI 是否存在 + 标题/期刊/年份 |
| 其余（出版社页、预印本、会议摘要） | 页面抓取 + 必要时浏览器通道升级 | 标题一致性 + 可达性 |

`--pmid-api` 会自动识别上述三类并跳过已核验条目的重复抓取。裸 HTTP 抓取会被 PubMed 限流（HTTP 203 + 站点名过渡页），脚本已把这类页面判为 BLOCKED 而非 MISMATCH——**BLOCKED 只说明通道被挡，不等于来源无效**。

## 失败处置表

| 现象 | 判定 | 处置 |
|---|---|---|
| 403 / CAPTCHA / 登录墙 | 本通道未取到 | 升级浏览器通道；仍失败 → 「待验证」，不进主证据 |
| 页面标题与声称不符 | 张冠李戴 | 换正确文献或删引用 |
| 卷期 / DOI / PMID 对不上 | 字段有误 | 删该字段；没有 DOI 就不写 |
| 只拿到摘要 | 未读全文 | 只能标 `[检索命中未读全文]`，不得当全文结论引 |
| 正文不支持该句 | 错引 | 回原文找真正支撑句改引，或删结论 |
| 两个来源矛盾 | 证据冲突 | 并列呈现 + 说明差异原因，不选一个当真理 |
| 同一研究的新闻稿 + 通稿 + 转述 | 只算 1 个来源 | 「≥2 独立来源」指互相独立的原始出处 |
| 链接失效但检索快照在 | 来源曾存在 | 记录原始 URL + 检索快照，标「待验证」 |

## 交付前最小清单

- [ ] `python scripts/citation_audit.py report.md` 退出码 ≤ 1（FAIL 为 0 条）
- [ ] 每条引用都读到正文，或已标「待验证」并写明尝试过哪些升级通道
- [ ] 没有一项 DOI/PMID/卷期页是凭记忆写的
- [ ] 所有专有名词经过存在性检索
- [ ] 每个关键结论有 ≥2 个独立来源，或已说明为何只有一个
- [ ] 引用编号与 URL、访问日期一一对应，无孤引、无悬空引用
- [ ] 检索日志可让他人原样复现
- [ ] RUO / 在研 / 已获批状态分清，适用范围有声明
- [ ] 数据均标注年份与版本
