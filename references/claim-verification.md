## 为什么需要第二关

第一关（真实）只证明"这篇文献存在、且就是我读的那篇"。第二关要证明"**这篇文献的正文确实支持我引用的那一句**"。两者失效模式不同：

| 失效模式 | 第一关能抓 | 第二关才能抓 |
|---|---|---|
| 编造文献、PMID 不存在 | ✅ | — |
| 张冠李戴（标题/DOI 错配） | ✅ | — |
| 文献真实但不支持该句（错引） | ❌ | ✅ |
| 过度引申（摘要说"相关"，报告写成"AUC 0.80"） | ❌ | ✅ |
| 样本量/口径错配（把 441 例子集说成 588 例队列） | ❌ | ✅ |
| 摘要与全文用词不一致（C-statistic vs AUC） | ❌ | ✅ |

## 三步流程

```
① 抽取论断   从正文提取每个引用编号支撑的具体断言（数字、方向性结论、适用范围）
              → 产出 claims.json / 论断台账
② 取来源依据 摘要不够就取全文：efetch 拿摘要，web-reader 拿 PMC/HAL/OA 全文
              → 摘录支撑或反驳该断言的原句（含页码/小节）
③ 判定       按下方档位逐条判定，写入台账；不支持的改引或删，无法判定的标"待验证"
```

## 判定档位

| 档位 | 含义 | 处置 |
|---|---|---|
| **确认** | 来源原句与报告表述一致（含数字、口径、适用范围） | 可保留 |
| **部分确认** | 结论方向一致但口径/范围需注明（如子集 vs 全队列、out-of-bag vs 外部验证） | 改措辞后保留，并在正文注明口径 |
| **不支持** | 来源未提及该数字/结论，或结论相反 | 改引正确来源，或删除该断言 |
| **待验证** | 仅拿到摘要、全文被墙、或需专业判断 | 正文加〔〕标注，列入待办 |

## 取证通道

| 需要什么 | 通道 |
|---|---|
| 摘要（全部 PubMed 收录文献） | `efetch.fcgi?db=pubmed&retmode=xml&id=<pmids>`（可批量，一次拿多篇） |
| PMC 免费全文 | `https://pmc.ncbi.nlm.nih.gov/articles/PMCxxxx/`（web-reader 可读） |
| HAL / 机构库全文 | 作者自存档 PDF 链接（web-reader 可读） |
| 出版社 OA 全文 | Frontiers / BMC / Nature / EHJ 等 OA 页面（web-reader） |
| 付费墙全文 | 先找 PMC/HAL/预印本版本；都没有则标"待验证"，不得凭摘要写具体数字 |

**铁律：报告里出现的每一个具体数字（样本量、AUC、NPV、基因数、年份、卷期页）都必须能在所引来源里找到原句。** 摘要里没有的数字，要么取全文确认，要么删。

## 论断台账

列：`引用编号, 报告论断, 来源(PMID/DOI), 取证通道, 来源原句, 判定, 处置`。模板见 [../assets/claim-ledger-template.csv](../assets/claim-ledger-template.csv)。

## 检查清单

- [ ] 每个引用编号至少提取到一条具体论断（无论断的编号 = 孤引，删）
- [ ] 每个含数字的论断都有来源原句支撑
- [ ] 口径已注明（训练/验证、内部/外部、子集/全队列、out-of-bag/嵌套 CV）
- [ ] 摘要与全文用词不一致时，以全文为准并在正文注明
- [ ] "不支持"的断言已改引或删除，没有硬留
- [ ] "待验证"的断言在正文有可见标注，并列入交付说明
